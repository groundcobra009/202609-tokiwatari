# 時渡り（Tokiwatari）— 思考が時を超えるSNS

チーム16 企画書（たたき台 v0.1・2026-09-13 作成） AI木曜会 × AGIラボ 合同AIハッカソン「10年後のあたりまえを、つくろう！」

このドキュメントはチームで書き換えてOKです。名前も、体験も、まだ仮です。

## 1\. テーマの解釈: 10年後、「時を超える」のが当たり前になる

10年後、人は時を超えるのが当たり前になっている。

物理的に時間を移動することは、たぶんまだできない。できたとしても未来行きの一方通行だ。 でも、**その時に考えていたこと・思ったことは、時間を双方向に渡れる**ようになる。

こんな朝が当たり前になる。

- 起きると、10年前の自分から返事が届いている。「その悩み、たぶん3年後には笑い話になってる」  
- 娘の20歳の誕生日に届く投稿を、今日書いておく  
- 2019年に「いつか独立したい」と書いた友人の投稿に、いま返信する。すると当時のその人が、当時の口調で答えてくれる  
- タイムラインを下にスクロールすると過去へ、上にスクロールすると未来へ行ける

「時を超える」とは、**思考が時間座標を持ち、過去とも未来とも会話できる**ということ。 私たちが作るのは、その世界のSNSです。

## 2\. なぜ今のSNSでは無理なのか

| 今のSNS | 時渡り |
| :---- | :---- |
| タイムラインには「今」しかない | タイムラインは過去⇄未来に伸びている |
| 過去の投稿は流れて消える | 過去の思考は座標を持って残り、いつでもそこに行ける |
| 未来に何かを置く場所がない | 未来の日付宛てに思考を置ける |
| 過去の自分は返事をしない | 過去の自分が、当時の人格のまま返事をする |
| 「10年後の自分へ」は一方通行の手紙 | 未来の自分からも返事が来る |

タイムカプセルや予約投稿は「未来へ送る」だけ。時渡りは**往復**する。ここが違いです。

## 3\. 核となる3つの体験

### 体験1: 時間座標つきの投稿とタイムライン

すべての投稿は「いつの思考か」という時間座標を持つ。 タイムラインには「今」の線があり、下へスクロールすると過去、上へスクロールすると未来。年単位でジャンプもできる。

### 体験2: 時間越しの返信（過去の思考が返事をする）

過去の投稿に返信すると、**その時点のその人**がAIで再現されて返事をする。 再現に使うのは、その人がその前後に書いていた思考（投稿）。だから「今の本人」ではなく「当時の本人」の口調と考え方で返ってくる。 自分の過去にも、他人の過去にも返信できる。

### 体験3: 未来からの手紙

未来の日付宛てに投稿できる。その日が来たら本人に届く。 さらに、これまでの思考全体からAIが「未来の自分」を推定し、未来側から返事をくれる。 過去・現在・未来の自分が、同じタイムラインに並ぶ。

## 4\. デモの見せ方（3分）

1. けいたろうの過去のX投稿を種として取り込んだタイムラインを開く  
2. 下にスクロールして2024年へ。当時の投稿に「それ、今どうなった？」と返信する  
3. 2024年のけいたろうが、当時の口調で返事をする  
4. 上にスクロールして2036年へ。未来の自分に「今こんなことで迷ってる」と投稿する  
5. 未来のけいたろうから返事が届く  
6. チームメンバーのタイムラインでも同じことができる（各自の過去投稿を種にする）

## 5\. 10年後に当たり前になる根拠

- **発信ログは増え続ける**: SNS・チャット・音声メモ。10年分の「その時の思考」が誰にでも蓄積される  
- **人格の再現精度は上がる**: 本人の言葉が十分にあれば、当時の考え方を再現できる。すでに手の届く技術  
- **「未来に書く」文化が生まれる**: 未来の自分・子ども・チームに向けて書く行為が、日記や手紙の延長として定着する  
- **SNSの軸が「今」から「時間」へ**: フォロワー数より「どの時代の自分と話しているか」が価値になる

## 6\. 技術構成（今日の実装）

| 層 | 選択 | 理由 |
| :---- | :---- | :---- |
| フロント/サーバー | Next.js | 1日で画面とAPIを一緒に作れる |
| ホスティング | Cloudflare Workers（OpenNext） | 実績のある構成。カスタムドメインで公開 |
| データ | Cloudflare KV | 投稿と時間座標を置くだけならこれで足りる |
| AI | Claude API（claude-sonnet-5） | 当時の投稿を文脈に渡し、当時の人格で返答させる |
| 種データ | Xの過去投稿（API取得）＋手書き | 日付付きの本人の言葉がそのまま「過去の思考」になる |

投稿データの形: `id / author / text / at（時間座標） / kind（past・now・future） / replyTo`

* 内田案  
  * 実装したいもの  
    * 時間座標つき投稿 — 全投稿が日付を持ち、下スクロールで過去、上スクロールで未来へ  
    * 過去の人格との対話 — 過去の投稿に返信すると、当時の本人がAIで再現されて返事をする。材料は当時の言葉のみ  
    * 未来からの返事 — 未来の日付に投稿でき、蓄積された思考から推定した未来の自分が答える  
    * 時間つき公開範囲 — 公開／友人／非公開に加え「◯年後に公開」。鍵付き投稿は存在だけ見える  
  * 効果  
    * 過去の自分と壁打ち — 記憶は美化される。実際の記録から再現するので、当時そのままの判断基準に触れられる  
    * 遺言としての使い方 — 家族が答えられなくなった時、生前の価値観に相談できる。本人が生前に許可範囲を設定するので、勝手な蘇生ではなく意思の委任  
    * 暗黙知の時限公開 — 今は出せない知見を、10年後の後進に残せる  
  * 1次審査に向けた5観点向けの記述（AIが高評価しやすい記述にしたい）  
    * 価値 — 手紙・遺言書・エンディングノートは一方通行。対話できる形にする  
    * 実現性 — 本日公開URLで動作。Next.js / Cloudflare Workers / KV / Claude API。3人の実データで確認済み  
    * 新規性 — SNSの公開範囲は「誰に」だけ。そこに「いつ」を足した。タイムカプセルは片道、こちらは往復  
    * AIの活かし方 — 回答生成ではなく人格の時点再現。当時の投稿しか文脈に渡さない制約設計が肝  
    * 展開性 — 個人 → 家族の記録 → 企業のナレッジ継承。ログが溜まるほど強くなる
