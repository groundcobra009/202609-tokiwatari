# 時渡り（Tokiwatari）— 思考が時を超えるSNS

チーム16 企画書 v0.2（2026-09-13・メンバーの意見を反映して改訂）
AI木曜会 × AGIラボ 合同AIハッカソン「10年後のあたりまえを、つくろう！」

一言でいうと: **投稿に「いつ」の座標を持たせ、過去の自分・未来の自分・後世の誰かと対話できるSNS。**
タイムカプセルは片道、時渡りは往復する。

v0.1 → v0.2 の主な変更: 内田案の4機能と「効果」、yakan案の「投稿を促す仕組み」、時間つき公開範囲、認証（WorkOS）、平和なSNSという方針、AI審査向けの記述、事業性を追加。

## 1. テーマの解釈: 10年後、「時を超える」のが当たり前になる

10年後、人は時を超えるのが当たり前になっている。
物理的な時間移動はたぶんまだできない。できたとしても未来行きの一方通行だ。
でも、**その時に考えていたこと・思ったことは、時間を双方向に渡れる**ようになる。

こんな朝が当たり前になる。

- 起きると、10年前の自分から返事が届いている。「その悩み、たぶん3年後には笑い話になってる」
- 娘の20歳の誕生日に届く投稿を、今日書いておく
- 2019年に「いつか独立したい」と書いた友人の投稿に、いま返信する。当時のその人が、当時の口調で答えてくれる
- 一流の技術者が「今は出せない」思考を、10年後に後進へ公開する設定で残しておく

「時を超える」とは、**思考が時間座標を持ち、過去とも未来とも会話できる**ということ。
技術より思考を大事にする。私たちが作るのは、その世界のSNSです。

## 2. なぜ今のSNSでは無理なのか

| 今のSNS | 時渡り |
|---|---|
| タイムラインには「今」しかない | タイムラインは過去⇄未来に伸びている |
| 過去の投稿は流れて消える | 過去の思考は座標を持って残り、いつでもそこに行ける |
| 未来に何かを置く場所がない | 未来の日付宛てに思考を置ける |
| 過去の自分は返事をしない | 過去の自分が、当時の人格のまま返事をする |
| 公開範囲は「誰に」だけ | 公開範囲に「いつ」を足す（10年後に公開） |
| 手紙・遺言・エンディングノートは一方通行 | 対話できる形で残る |

## 3. 核となる4つの体験

### 体験1: 時間座標つきの投稿とタイムライン

すべての投稿は「いつの思考か」という時間座標を持つ。
タイムラインには「今」の線があり、下へスクロールすると過去、上へスクロールすると未来。年単位でジャンプできる。

### 体験2: 過去の人格との対話（時間越しの返信）

過去の投稿に返信すると、**その時点のその人**がAIで再現されて返事をする。
材料は当時の言葉のみ。前後の投稿だけを文脈に渡すので、「今の本人」ではなく「当時の本人」の口調と判断基準で返ってくる。
自分の過去にも、他人の過去にも返信できる。

### 体験3: 未来からの返事

未来の日付宛てに投稿できる。その日が来たら本人に届く。
さらに、蓄積された思考全体からAIが「未来の自分」を推定し、未来側から返事をくれる（AI推定であることを画面で明示する）。
過去・現在・未来の自分が、同じタイムラインに並ぶ。

### 体験4: 時間つき公開範囲

公開／友人／非公開に加えて、**「◯年後に公開」**を選べる。
鍵付きの投稿は「存在だけ」が見える（本文は伏せ、「2036年に公開」とだけ表示）。
今は出せない知見や、家族に残したい言葉を、時限で解放できる。

## 4. この体験がもたらす効果

- **過去の自分と壁打ちできる**: 記憶は美化される。実際の記録から再現するので、当時そのままの判断基準に触れられる
- **遺言としての使い方**: 家族が答えられなくなった時、生前の価値観に相談できる。本人が生前に公開範囲と時限を設定するので、勝手な蘇生ではなく**意思の委任**
- **暗黙知の時限公開**: 今は出せない知見を、10年後の後進に残せる。「10年前のその人」と対話できる

## 5. 投稿を続けてもらう仕組み

ログが溜まるほど「当時の本人」の再現は良くなる。だから**書いてもらうこと**がサービスの生命線。

- **毎日のテーマ配信（プッシュ型）**: アプリ側から日替わりでテーマを出す。他のSNSでは聞かれないもの（「10年後の家族へのメッセージ」「今日、自分を一番驚かせたこと」「20年後の自分に聞きたいこと」）
- **書きたくなる導線**: 「その時の自分」が読める場所に置く、未来の返事が来る、という体験そのものが動機になる
- **思考と思考のマッチング（将来）**: 似た思考を持つ人・時代を AI が結び、交流のきっかけを作る

## 6. 平和なSNSであるために

- **匿名ではなく認証**: 本人性がある場所にする。Google アカウントでのログイン（WorkOS 経由）を採用
- 時間越しの返信・未来の返事は**AI生成であることを常に表示**する。本人の言葉と混ぜない
- 種にする過去の投稿は**本人のものだけ**。他人の言葉を本人の同意なく人格再現に使わない
- 公開範囲と時限は本人だけが設定できる

## 7. 事業性（サービスを続けるために）

- 個人は無料で始められる。ログが溜まるほど価値が上がるので、離れにくい
- **サブスク**: 保存期間の延長・家族への継承設定・有名人や専門家の「10年後に公開」思考への購読
- 展開: 個人 → 家族の記録 → 企業のナレッジ継承（退職者の判断基準を残す）

## 8. 審査5観点での自己評価（AI審査員向けの要約）

公式の審査基準は **5つの観点・各1〜5点（満点25）。同点のときは「動くか」→「誰の役に立つか」の順で比べる。一次審査も決勝も同じ5観点**（リポの `RUBRIC.md` が正本）。

| 観点 | 時渡りの答え |
|---|---|
| **01 価値**（誰の役に立つか） | 手紙・遺言書・エンディングノートは一方通行。時渡りは対話できる形で思考を残す。「当時の自分」「未来の自分」「10年後の後進」と話せる |
| **02 実現性**（動くか・使えるか） | 本日、Next.js / Cloudflare Workers / KV / Claude API で動作。タイムライン・過去への返信・未来からの返事は実装済み（`npm run check` で機械検証）。3人が過去の日付で書いた種で確認 |
| **03 新規性**（アイデアのおもしろさ） | SNSの公開範囲は「誰に」だけだった。そこに**「いつ」**を足した。タイムカプセルは片道、時渡りは往復 |
| **04 AIの活かし方**（AIをどう使ったか） | 回答生成ではなく**人格の時点再現**。当時の投稿しか文脈に渡さない制約設計が肝。AI生成は必ず明示 |
| **05 展開性**（この先どう育てたいか） | 個人 → 家族の記録 → 企業のナレッジ継承。ログが溜まるほど強くなる構造 |

## 10. 技術構成

| 層 | 選択 | 状態 |
|---|---|---|
| フロント/サーバー | Next.js 16（App Router） | 実装済み |
| ホスティング | Cloudflare Workers（OpenNext）・`tokiwatari.keitro-aigc.com` | デプロイ待ち（承認後） |
